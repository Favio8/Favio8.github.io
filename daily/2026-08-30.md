## 今日进展

- 读了三篇 Agent 运行时（runtime）相关的工作，重点看它们怎么处理**工具调用的安全边界**。
- 画了一版分层图：意图层 / 权限层 / 执行层 / 观测层，四层之间用一个统一的 `Capability` 对象串联。
- 把「Agent OS」这个概念拆成可落地的三个问题：能不能调、调了会怎样、出事能不能回滚。

## 读到的有意思的点

- 现有方案基本都卡在同一个地方：**权限是一次性授予的，但风险是逐次累积的**。一个看起来无害的工具，调 20 次之后可能就构成了危险行为。
- 沙箱的价值不只是安全，还有**可恢复性**。能回滚的执行环境，才敢让 Agent 放手去做。
- 「最小权限原则」在 Agent 场景落地很别扭：你没法预先知道一个自主 Agent 到底需要哪些权限。

## 遇到的问题

- 想找一个统一的权限描述语言，看了 OAuth scope、FGA、以及几个 Agent 框架自己的实现，没有一个能直接复用。
- 分层图画完之后发现「观测层」和「执行层」耦合很重，观测依赖执行的返回值，执行又需要观测来做中断判断，还没拆干净。
